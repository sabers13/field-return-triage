# R3 - Similar past cases

## What was built

`src/field_return_triage/similar/` implements PLAN.md §4 step 4 and §9:

| Module | Public surface | Purpose |
|---|---|---|
| `embedder.py` | `Embedder`, `default_embedder()`, `EMBEDDING_MODEL`, `EMBEDDING_REVISION`, `EMBEDDING_DIMENSIONS` | `BAAI/bge-small-en-v1.5` on CPU, pinned to revision `5c38ec7c405ec4b44b94cc5a9bb96e735b38267a` (the same pin as which-ai-model's `rag/embed.py`). The model is imported and loaded lazily, only when `make index` runs. |
| `index.py` | `build_index()`, `load_index()`, `cache_dir()`, `index_path()`, `checksum_key()` | Embeds the library once and writes `ids`, L2-normalised float32 vectors, model name and data key to `~/.cache/field-return-triage/index-<sha256(data/CHECKSUMS.txt)[:16]>.npz`. A changed library therefore never reuses old vectors. The data key is read before any embedding work, so a missing `data/CHECKSUMS.txt` fails immediately. |
| `search.py` | `search()`, `nearest()`, `excerpt()`, `EXCERPT_CHARS` | numpy brute-force cosine similarity. Scores are rounded to 4 decimals **before** ranking; ties break on complaint id ascending. `k <= 0` is rejected. Each `Neighbour` carries id, group (`unclear` when the library row has none), received date, coded safety flag and the first 200 characters of the whitespace-normalised narrative. |
| `evaluate.py` | `precision_at_k()` | PLAN §6 similar-cases metric: mean share of each query's nearest neighbours that share its group. Queries without a group contribute zero; fewer than `k` available neighbours are scored over the neighbours that exist, never padded. |
| `cli.py` | `index_main()` | `frt index` / `make index`. Reads `data/library.jsonl.gz` directly (the lane does not import `data`; contracts are the shared surface), prints item count, elapsed time and cache path. |

`make index` runs `uv run --extra index python -m field_return_triage.similar.cli`.

## Tests

38 new tests in `tests/similar/`, all offline, with a deterministic `FakeEmbedder`:

- index: cache location outside the repo, checksum-keyed file names, round trip of ids and normalised vectors, rejection of empty libraries, duplicate ids, wrong vector counts, corrupt archives, a different model pin, and missing checksums before embedding;
- search: ordering, 4-decimal rounding, id tie-break, neighbour fields, coded crash/fire/injury safety, excerpt normalisation and 200-character truncation, `k` bounds, empty index, id/library mismatch, dimension mismatch;
- evaluation: precision@1 and precision@5 on known vectors, fewer-than-`k` neighbours, empty queries, a query without a group, `k` bounds;
- embedder: pinned model and revision, no `sentence_transformers` import at package import, empty input without loading weights, batch-size validation, one process-wide default instance;
- CLI: end-to-end `index_main` on a temporary gzipped library, plus its error paths.

`make test`: **249 passed** (the 38 new tests plus the existing suite). `ruff check`, `ruff format --check` and strict `mypy` are clean. `make scan-forbidden` and `make scan-secrets` pass.

## `make index` timing

R1's committed derived data is **not on `main` yet** (`data/` contains only `feedback/`), so the exact acceptance run on `data/library.jsonl.gz` is still open. To verify the real model path end to end I built a temporary, uncommitted 20,000-row library from the X0 NHTSA snapshot (`~/.cache/nhtsa-snapshot/2026-10-31/COMPLAINTS_RECEIVED_2020-2024.txt`): real narratives of at least 80 characters, one row per `CMPLID`, and a coarse stand-in component-group mapping. The rows are valid `Complaint` contracts; only the selection and group labels differ from R1's derivation.

```
make index
frt index: embedded 20000 complaints in 897.6s -> ~/.cache/field-return-triage/index-9a8a36e5262b400a.npz
wall=902.16s  maxrss=1273512KB
```

The 897.6 s is the first (cold) run: it includes the one-time Hugging Face model download and load, not just encoding. The cache file was 20 MB (384 dimensions × 20,000 float32 values plus ids). The temporary library, checksum file and cache entry were removed afterwards; the worktree contains no data-lane files.

## Shared-file changes (and why)

- `pyproject.toml`: added `numpy==2.5.4` (the search is numpy brute force) and an optional `index` extra with `sentence-transformers==6.2.0` and `torch==2.9.1`, using the CPU-only PyTorch index and source pin from which-ai-model. Keeping torch out of the default environment keeps the test suite and the other lanes light; only `make index` syncs the extra. Added a mypy override for `sentence_transformers.*`, which ships no type markers.
- `uv.lock`: regenerated for the two additions.
- `Makefile`: replaced only the `index` stub recipe; the target name and help text are unchanged.
- `tests/test_cli.py`: removed `index` from the parameterised "simple stubs" list, because the command is now implemented. The command still appears in the help test.

## Deviations

None from PLAN.md. The evaluation metric is implemented but not wired into R6's evaluation runner; R6 can call `precision_at_k` once the real library and eval set exist. This matches the brief's allowance to drop the evaluation and keep the search.
