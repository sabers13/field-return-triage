Status: done. Branch `fm/frt-r4`, based on the scaffold on `main` (R0). `make test`,
`make lint` (Ruff check + format check), `make typecheck` and `make scan-forbidden` are
green.

## What was built

### `src/field_return_triage/rules/`

- **`rulebook.py`** — `Rule`, `Rulebook`, `load_rulebook()`, `RULEBOOK_PATH`,
  `RULEBOOK_VERSION`. Loads `config/rulebook.toml` with `tomllib`, validates the version
  (`rb1`), the kind vocabulary (the fixed symptom and condition kinds only) and the shape
  (a rule needs at least one test), and freezes the result (`MappingProxyType`, frozen
  dataclasses). A broken rulebook raises; it never silently falls back to the standard
  test.
- **`keywords.py`** — `load_safety_keywords()`, `keyword_safety()`. One keyword per line,
  comments and blanks ignored, duplicates removed in first-seen order; an empty list is
  an error because it would silently switch the keyword rule off. Matching is
  case-insensitive, tolerates any whitespace inside a multi-word keyword, and returns
  the exact narrative span that matched (earliest span wins; ties go to the longer span).
- **`hard_rules.py`** — `hr1` as pure functions:
  - `decides_safety(complaint, extraction, keyword_quote) -> (safety, reasons)`, in a
    fixed order: the model's flag with its quote, the keyword span, then the coded
    crash/fire/injury fields.
  - `route(..., *, safety) -> (priority, needs_human_review)`. Safety is priority 1 and
    human review, and wins over every other branch; the coded fields are re-checked
    inside `route` so a caller cannot lose safety by passing `safety=False`. An unclear
    group or no passing clue is priority 3 and human reading; anything else is priority 2.
  - `suggest(extraction, quote_check, rulebook)`. Uses only clues that passed the quote
    check; one `Reason` per matched kind, carrying that kind's quotes. Tests, inspections
    and requests are deduplicated in first-seen order. "Fault codes" is requested whenever
    no fault code survived the check. With no condition and no specific symptom it returns
    exactly the PLAN §4 fallback: `standard test` plus "when it happens, how often, under
    which conditions, fault codes".
  - `build_card(...)`. Assembles the card: priority, human-review flag, safety reasons
    plus one routing reason, every honest quote (safety span, keyword span, kept symptoms,
    conditions, fault codes, mileage; dropped clues excluded), the neighbours slot, the
    suggestion, and the four versions (`e1`, `rb1`, `hr1`, model id) with an injected
    clock. Deterministic for the same inputs.
  - There is no close, scrap or return field, function, enum member or decision in the
    module. Card ids are `"<complaint id>:<model id>"`.
- **`feedback.py`** — `append_decision()`, `load_decisions()`. One sorted-key JSON line per
  decision, append-only, directory created on demand; a missing log is empty; a corrupt
  row raises with its file and line.
- **`kpi.py`** — `acceptance_rate()`, `change_reasons()`, `median_time_to_decision_s()`,
  the definitions the page shows. An empty log gives `None`, not a made-up zero.
- **`cli.py`** — `frt review` (`review_main()`). Shows the first undecided card as a
  readable terminal card (priority, narrative, kept clues with their quotes, why, the
  suggested test with its reasons and quotes, neighbours, versions), then reads one
  decision:
  - `accept` → accept with no reason;
  - `change <text>` → change with that reason;
  - `reason <text>` → accept with a note;
  - bare `change` asks for the reason until one is given.

  Cards come from the newest `results/runs/*/cards.jsonl`, or `FRT_CARDS_FILE`; the log
  defaults to `data/feedback/decisions.jsonl`, or `FRT_DECISIONS_PATH`. A card that
  already has a decision is skipped, and the command says so when every card is decided.
  An invalid verb (including `close`) is rejected and re-prompted.

### `config/rulebook.toml` (`rb1`)

The seven mappings from PLAN §4 with their exact wording (test and inspect), the exact
standard-test fallback, and a header comment saying plainly that this is an example to
adapt to a lab's own test catalogue. It also carries an example rule for every remaining
fixed kind (`speed_or_load`, `startup`, `no_function`, `warning_light`, `smoke_or_burn`,
`noise`, `display_fault`, `battery_drain`) so a card with a specific symptom is never
silently treated as "no clue". The `other` kinds are deliberately absent and fall back.

### `data/feedback/example.decisions.jsonl`

Two committed example rows (one accept, one change) so the log format is visible; every
other file in `data/feedback/` is gitignored by the R0 `.gitignore`.

## How it was tested

`tests/rules/` (96 new tests; 143 in the whole suite):

- **`test_rulebook.py`** — the committed file maps the PLAN table exactly, the fallback is
  exact, every rule has a test, the structure is immutable; a wrong version, unknown kind,
  empty test list, empty list item and empty fallback test are each rejected.
- **`test_keywords.py`** — comment/blank handling, dedupe, empty-file error, case-insensitive
  match returning the narrative span, flexible whitespace in multi-word keywords, word
  order, earliest span wins, no match, empty keyword ignored.
- **`test_hard_rules.py`** — each safety source alone and all three together in fixed
  order; no source → not safety; safety routes to priority 1; coded safety survives
  `safety=False`; unclear group, zero passing quotes and zero clues each route to
  priority 3 + human review; clear clues route to priority 2; a parametrised matrix proves
  safety wins over unclear/clear and over zero/passing quotes. Suggestions: rulebook
  mapping, condition-before-symptom order, reasons and quotes, fault-code request, dropped
  clue ignored, exact fallback, `other` falls back, the shared `intermittent` kind,
  dedupe. Cards: versions, clock, neighbours, quote selection with drops (including a
  dropped safety quote not demoting a safety card), fault-code and mileage quotes,
  determinism, reason objects with quotes.
- **`test_no_auto_close.py`** — the no-auto-close property over the reachable contract
  types (no field word close/scrap/return/disposition/outcome/status), the decision
  vocabulary is exactly `accept|change`, no rules function or new model names one, and a
  serialised card (unsafe/unclear quadrants) has no such key at any depth.
- **`test_feedback.py`** — append/load round-trip, sorted keys, missing log, blank lines,
  corrupt JSON and invalid rows naming their line, `change` without a reason refused, and
  the three KPIs including the empty-log `None` and sorted change reasons.
- **`test_review_cli.py`** — accept, inline change, bare change with a reason, reason-line
  accept with a note, `close` rejected and re-prompted, second run skips a decided card,
  "no undecided cards", missing cards file, malformed card line, and a safety card shown
  as priority 1 + human review.

A manual run on a demo card confirmed the terminal rendering and that one `accept`
appends one line; the demo files were written outside the worktree, under the task folder.

## Deviations and judgement calls

- **`pyproject.toml`** — added one Ruff per-file ignore,
  `"src/field_return_triage/*/cli.py" = ["T201"]`. `docs/INTERFACES.md` promises every lane
  CLI may print; only the root `cli.py` carried the exemption. Without it this lane's CLI
  cannot print without a blanket ignore.
- **`tests/test_cli.py`** — removed `review` from the "simple stubs" parametrisation,
  because `frt review` is no longer a stub. The command stays in the help-listing set. This
  is the expected collision when a lane replaces its stub.
- **`data/feedback/example.decisions.jsonl`** — the brief requires a committed example in a
  gitignored directory; `data/` is otherwise the data lane's, so this is a deliberate small
  addition outside the lane's named paths.
- **Extra rulebook kinds.** PLAN §4 fixes seven mappings; the file also gives an example
  rule for the remaining fixed kinds (header says it is an example to adapt). The seven
  PLAN rows are tested to match exactly.
- **Safety with a dropped safety quote.** A quote that fails the check is dropped from the
  card's quotes, but the model's safety flag still routes the card to priority 1. Dropping
  the flag would let a failed quote hide a safety case, which hard rule 1 forbids. Tested.
- **Keyword matching is substring-based** (case-insensitive, no word boundaries), so a
  keyword inside a longer word or a negated sentence can over-flag. That is the safe
  direction for a safety rule and leaves the precision/recall trade-off visible to the
  PLAN §6 safety metrics rather than hidden in the matcher.
- **`frt review` card source.** `review_main()` takes no arguments (as INTERFACES fixes),
  so it discovers the newest run's `cards.jsonl` with an env override. R6 writes those
  files; until then the command fails with a clear message rather than a traceback.
- **`reason <text>`** records an acceptance with a note. `contracts.DecisionAction` has only
  `accept|change`, so a reason-only decision has no action of its own; recording it as an
  accept-with-note keeps the brief's three literal forms without changing a frozen type.
