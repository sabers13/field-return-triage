# R1 - Data

## What was built

`src/field_return_triage/data/` implements the data lane against the binding X0 spec
(`data/nhtsa-spec.toml`, copied byte for byte) and the frozen `Complaint` contract.

| Module | Public surface | Purpose |
|---|---|---|
| `spec.py` | `load_spec()`, `load_groups()`, `normalise_component()`, `map_component()` | Reads the two normative TOML files. Component matching is trim + uppercase + collapse whitespace + no spaces around `:`, then the **longest** prefix that equals the value or starts with `prefix:`. Unmapped values are `None`. Also holds the split window and the four PII regexes as constants. |
| `parse.py` | `parse_complaint_rows()`, `parse_recall_rows()`, `read_archive_lines()` | TAB parsing from the zipped downloads without extraction: 51 complaint fields, 29 recall fields, no header, UTF-8, CR stripped from the CRLF recall file. A wrong field count names the line. |
| `pii.py` | `pii_reason()`, `pii_matches()` | The spec's four normative patterns (17-character VIN, e-mail, US phone, street address). Any match drops the whole narrative; nothing is redacted in place. |
| `complaints.py` | `resolve_complaints()`, `screen_narratives()`, `derive_library()`, `derive_eval()`, `split_half()`, `complaint_from_row()`, `coded_safety_row()` | Vehicle filter, single-group rule, 80-character minimum, PII screen, train/test windows, `frt` halving and the stratified deterministic sampler. |
| `weekly.py` | `derive_weekly()`, `week_start()` | Counts-only trend table: all single-group complaints, Monday ISO weeks, make + model + model year + group. No narrative length or PII filter, by design. |
| `recalls.py` | `resolve_recalls()`, `derive_recalls()`, `resolve_recalls_with_stats()` | Vehicle recall rows whose `COMPNAME` maps to a group, joined key fields and `RCDATE`. Unmapped rows are skipped and counted. |
| `io.py` | `write_*` / `load_*` | JSONL (keys sorted, UTF-8, `\n`), gzip with `mtime=0` for byte-identical reruns, and the two CSV headers from `docs/INTERFACES.md`. Writers return the sha256 of the written bytes. |
| `fetch.py` | `ensure_inputs()`, `sha256_file()` | Uses a snapshot file only when its sha256 matches the spec; otherwise uses a matching `data/raw/` copy or downloads to `data/raw/`. A changed checksum is a warning, never a stop. |
| `stats.py` | `build_stats()` | Deterministic `data/STATS.md`: funnel, per-group counts, natural vs sampled safety rates, PII drops and recall mapping. |
| `cli.py` | `data_main()` | `frt data` / `make data`: fetch, derive, write, checksum, statistics. |

`scripts/fetch_nhtsa.py` is `make fetch-data`: it resolves the five inputs and prints
each source and checksum state.

### The derivation, exactly

- Only `PROD_TYPE == 'V'` rows count (the 7 blank-type rows in the snapshot are out).
- A complaint counts only when every component row maps to one and the same group; one
  unmapped row or two groups excludes the whole complaint.
- Narrative: trimmed, at least 80 characters, then the PII screen.
- Library: `LDATE` 2020-01-01 … 2024-12-31, cap 20,000, stratified by group.
- Evaluation: `LDATE` 2025-01-01 … 2026-10-31, `frt` half only, 400 items, at least 20
  per group and at least 80 safety-relevant. The safety top-up is the spec's swap.
- Halving: `int(sha256("20261031:" + ODINO), 16) % 2`, 0 = `wam`, 1 = `frt`.
- Sampling order: ascending full hex `sha256("<seed>:<ODINO>")`; quotas start at
  `min(min_per_group, pool)` and the remainder is shared by largest remainder, capped at
  the pool. Same seed and same rows give the same sample under any input order.
- Trend: every single-group complaint, no narrative filters; recalls: vehicle rows with a
  mapped group only.

## Tests

67 new tests in `tests/data/`, all offline and built from in-memory fixtures (no snapshot
read):

- **parsing**: field counts, named fields, CR stripping, blank lines, wrong-count errors,
  zip-member reading, and the committed field lists partitioning exactly as the spec says;
- **column drop**: the derived contract has no identity/location field, and a written
  eval file contains none of the planted VIN/city/dealer values;
- **single-group rule**: same-group kept, one unmapped excluded, two groups excluded,
  non-vehicle excluded, order-independent;
- **each PII pattern**: VIN, e-mail, phone (two formats), street (two suffixes), a clean
  narrative, overlapping matches, and the constants checked against the committed spec;
- **halving rule**: `split_half` equals the spec formula for 40 ids, eval keeps only odd
  hashes and 2025+ dates, eval is disjoint from the `wam` half and from the library;
- **sampling**: proportional quotas, a small group fully used at capacity, limit above
  pool, group floor, safety top-up to 80, shuffled-input determinism, a different seed
  changing the draw, overdraw and too-small-size errors;
- **trend tables**: Monday weeks, per-series aggregation, missing/`9999` years skipped,
  ordering, recall mapping and vehicle filtering.
- **format and stats**: round trips for all four files, gzip determinism, bad headers/rows,
  `STATS.md` sections and stable output.

`make test`: **374 passed** (67 new). Ruff check and format, strict mypy (48 files),
`make scan-forbidden` and `make scan-secrets` are clean.

## Interpretations and deviations (for the reviewer)

1. **Derived-row schema.** The spec's `[derived]` list includes `failure_date`, `mileage`,
   `injured`, `deaths`, `period` and `split_half`. The frozen `Complaint` contract
   (R0/`docs/INTERFACES.md`) has none of these; JSONL rows must be one contract per line.
   The committed rows therefore carry `id`, narrative, received date, make, model, model
   year, raw component, group and the three coded flags. `injury` is true when
   `INJURED > 0` **or** `DEATHS > 0`, so `coded_safety` still equals the spec rule. The
   extraction stage reads mileage from the narrative anyway.
2. **Library allocation.** `[sampling.train]` names no `min_per_group`, so the library
   sampler starts every quota at zero and shares the cap proportionally. Small groups get
   their proportional share (e.g. 77 windows items), not their entire pool. The library is
   still stratified by group and capped at 20,000.
3. **Street pattern case.** The spec's street regex is case-sensitive on the suffix
   (`STREET`, not `Street`), and it is applied exactly as written, with no flags. On this
   snapshot it drops 1,183 narratives among the length-eligible complaints; the scout
   counted 1,184 on the unfiltered 49,033. A mixed-case address whose suffix is title-case
   would not match. This is the binding pattern, so the lane does not widen it; it is
   worth a follow-up decision if the screen is ever re-opened.
4. **Recall skips.** A recall row whose model year is `9999` or whose `RCDATE` is not a
   valid `YYYYMMDD` is skipped, never guessed, per the spec's "9999 never joins".
5. **No `reports/DEVIATIONS.md` entry.** None of the above changes `PLAN.md` §1-§11; they
   are implementation choices inside the binding spec and the frozen contract.

## Open issues

1. **R3 `make index` on the real library** is still open (R3's own follow-up); the file
   format and `CHECKSUMS.txt` key are in place.
2. **R5 `results/trend/`** is not committed here; R5 owns it and can now run `make trend`
   unchanged (verified above on a scratch directory).
3. The committed library is 3.6 MB and the recall CSV 4.8 MB, so `main` grows by about
   9 MB. That is the price of a self-contained replay path; the raw downloads stay
   gitignored.
4. The eval safety top-up concentrates the 80 safety items in `airbags` (65 of 75 selected
   airbag items are safety-relevant). That follows the spec's "take the group with the
   most unselected safety items" rule; R6's safety metrics should be read with it in mind.
