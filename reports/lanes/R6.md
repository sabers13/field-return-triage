### Behaviour that matters

- **Budget guard (PLAN §8).** Record mode estimates the conservative cost before each
  model. If the comparison model would cross the USD 3 cap, it is cut to the first 200
  items and the cut is reported in `metrics.json`. If the estimate still crosses the
  cap, or the next single call would, the runner raises `BudgetExceededError` and makes
  no further call. A policy stop (403/abuse) propagates, keeps the cards already
  written and leaves an `"incomplete": true` manifest.
- **Resumability.** `cards.jsonl` is the resume ledger: an existing `(model, complaint)`
  card is never called again. In replay the committed `<recordings>/calls.jsonl` sidecar
  also defines the plan, so a run that was reduced to 200 comparison items replays
  exactly those 200 instead of asking for missing recordings.
- **Determinism.** `REPLAY_NOW` (the 2026-10-31 snapshot instant) stamps replay cards and
  manifests; cards are rewritten sorted by item order then model order; metrics and
  summary JSON use sorted keys. Two `make all` runs are byte-identical.
- **Cost and speed.** Record mode measures each call and appends one row to
  `<recordings>/calls.jsonl` with run id, model, complaint, cost, duration and failure.
  Replay reads it back: the frozen recordings still hold content and usage only, while
  cost per 1,000 and latency p50/p95 remain available in replay.
- **`make all`.** `data-check → index-cached → trend → results`, then `page-data` and
  `page`. Until R8 adds `src/field_return_triage/report/`, the last two are skipped with
  a one-line note; the moment the report package exists, the same target runs them.
  `index-cached` reuses the R3 index and only builds it when missing; fixture mode uses
  an in-process deterministic hashing embedder, so fixtures need no torch download.

### Fixtures (`tests/fixtures/recordings/`)

20 fake evaluation complaints, a 10-item fake library, two fake models
(`fixture-primary`, `fixture-comparison`), their recordings keyed exactly as R2's
`recording_key`, and the `calls.jsonl` sidecar. One comparison answer is deliberately
unparseable so the invalid-answer path is exercised end to end. Fixture costs and
durations are fixed, so metrics include cost and latency with stable intervals.

## How it was tested

`tests/pipeline/` (50 tests, offline, sockets blocked):

- **flow** — a fixture replay card is grounded and routed to clear clues; safety wins on
  a recorded safety case; an `unclear` group goes to human reading; an invalid answer
  becomes a human-reading card with a `schema-invalid:` reason; a paraphrased quote is
  dropped and the card falls back; `triage_text` works on raw text; the rendered card
  says a technician decides; no serialised card carries a close/scrap/return key.
- **runner** — 40 cards, manifest and metrics on replay; two replay runs are
  byte-identical; resume after `limit=5` produces 40 unique cards; the budget cut leaves
  400 primary and 200 comparison cards with the cut logged; a too-small cap raises
  before any call and leaves an incomplete manifest; a policy stop keeps the two cards
  already written, writes the STOP notice and stops; a replay miss raises.
- **metrics** — known macro-F1 (including `unclear` as wrong), accuracy/coverage/answered
  accuracy, Wilson edges, final vs model-only safety recall/precision, quote grounding,
  condition agreement, routing, precision@5, latency and cost intervals, undefined
  metrics as `None`, and length checks.
- **baselines** — a learned group baseline scores 1.0 on a separable fixture, is
  deterministic, the safety baseline uses coded fields, condition coverage is exact,
  empty inputs say so, and the files are byte-identical.
- **make all** — the whole chain on fixtures, twice: identical bytes, the fixture warning
  and source paths in `SUMMARY.md`, no `MANIFEST.sha256` self-reference, one changed
  result changes exactly one manifest line.
- **CLI** — `frt triage` on a file and on stdin (JSON + text), a missing file, `frt eval`
  with `--models`/`--run-id` writing a run, `data-check`, and the fixture `index-cached`
  no-op. The root CLI test now lists all six commands and checks the new eval options.

`make test`: **423 passed**. `make lint`, `make typecheck`, `make scan-forbidden` and
`make scan-secrets` are clean.

## R3 follow-up — `make index` on the committed library

R3's open follow-up asked for one real `make index` run on R1's committed
`data/library.jsonl.gz`. The code path and cache key are unchanged from R3. On this
worktree (20,000 complaints, CPU, warm Hugging Face cache):

```
make index
frt index: embedded 20000 complaints in 1769.2s -> ~/.cache/field-return-triage/index-f1cc46e4f69437c4.npz
wall=29:30.30  maxrss=1247036KB
```

The 1769 s is the model-warm, vector-cold run: the embedding model was already in the
Hugging Face cache, only the 20,000-item encoding was new. It is slower than R3's
897.6 s because this worktree shared an 8-core machine with several other lanes at load
average 16; the process ran at about 2.3 cores. The cache key is
`sha256(data/CHECKSUMS.txt)[:16]` = `f1cc46e4f69437c4`, unchanged from R3. The cache file
is 28,594,175 bytes (27.3 MiB; 384 dimensions x 20,000 rows) and stays outside git.
This closes R3's follow-up.

## Shared-file changes and deviations

1. **`src/field_return_triage/cli.py`** — R0 owns this file and says lanes never edit it,
   but the brief's `frt eval --mode replay|record --models … --run-id …` needs two new
   options. The change is additive: the existing command and dispatch stay, the two
   options are passed to `eval_main`, and `eval_main` accepts them as optional arguments.
   No other line moved.
2. **`docs/INTERFACES.md` §8** — the R6 section now documents the extra keyword-only
   `run_eval` parameters, the `calls.jsonl` sidecar, fixture mode, `Metric.value = None`,
   the `Metric`-typed routing/latency returns, and the `make all` page fallback. These
   are additive clarifications of what R6 built; no other lane's section changed.
3. **`Makefile`** — replaced only R6's `eval-replay`, `results` and `all` recipes and
   added `data-check` and `index-cached` (used by `all`). Target names/help text for
   other lanes are unchanged. `all` skips `page-data`/`page` only while `report/` is
   absent.
4. **`tests/test_cli.py`** — the `triage` and `eval` stub assertions became real-command
   tests (their lane has landed); the help test still lists every command.
5. **`results/` and the summary/manifest** — the R6 brief assigns `SUMMARY.md` and
   `MANIFEST.sha256` to this lane, while `docs/INTERFACES.md` §9 gives `report` the same
   functions. R6 implements them in `pipeline/summary.py` because the page lane does not
   exist yet. R8 may call them from `make page-data` after writing `results/page/`, so
   the manifest covers the page files too; no name or path changes are required.
6. **Fixture-mode fallback** — rather than fail before R7, `resolve_paths` falls back to
   `tests/fixtures/recordings/` when `config/models.lock.toml` is absent. This keeps
   `make all` runnable on every commit; the run id is `fixture` (not `live`), the model
   ids are `fixture-*`, and the summary says plainly that these are not model results.
7. **`calls.jsonl` sidecar** — PLAN §9 says a recording row holds content and usage only.
   That is still true of the recording rows; cost and duration live in a separate
   `calls.jsonl` under the same recordings directory, because the frozen card cannot
   carry them and replay must not read the wall clock. R7 commits it with the
   recordings.
8. **Baseline implementation** — TF-IDF + multinomial logistic regression is written in
   numpy (fixed vocabulary order, zero init, fixed mini-batch order) rather than adding
   scikit-learn. It scores macro-F1 0.415 and accuracy 0.703 on the real 400-item eval
   set (a scratch run, not committed; the committed baseline files are the fixture
   ones until R7 regenerates them).
9. **`--limit`/smoke runs** — `run_eval(limit=…)` exists and is tested, but the CLI does
   not expose it; R7 can call the function or add the option in its own lane.
